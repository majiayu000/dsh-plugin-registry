REGISTRY POLICY

收录 · 本站规则

怎样进入公开列表。

这里说明 Harness Registry 自己执行的发现、验证和治理规则。本页就是本站完整规范，所有入口均在站内完成。

01

自动收录条件

仓库必须同时满足以下条件，缺少任何一项都不会进入公开插件列表。

  1. 公开且可访问同步任务必须能读取仓库元数据和根目录 package.json。
  2. 带有发现标记仓库需声明 dsh-plugin Topic，供定时任务发现。
  3. 声明可安装 bundle根目录 package.json 的 dsh.bundle.patch 必须是安全的相对路径。
  4. 状态符合要求已归档仓库和 Fork 不会自动进入公开列表。
02

Manifest 最低契约

patch 路径不能是绝对路径，也不能通过 .. 跳出仓库目录。对应文件需要随仓库一同维护。

{
  "dsh": {
    "bundle": {
      "patch": "./cordis.patch.yml"
    }
  }
}
03

本站显示的状态

状态说明的是本站验证到了什么，不代表对插件代码作出安全背书。

Manifest 格式检查通过
自动发现，并通过根目录 bundle 格式校验；可进入公开列表。
来源：社区目录
从社区维护的公开目录同步；本站没有检查其 Manifest、功能质量或安全性。
待审查
仓库已被发现，但尚未满足可安装契约，不出现在公开安装列表。
已隔离
因误收录、重复、风险或治理决定被排除，不出现在公开列表。
04

验证边界

本站只检查公开元数据和 manifest 结构，不运行插件代码，不验证安装后的行为，也不持续监控权限变化。

复制安装命令只代表命令已进入剪贴板，不代表插件已经安装。安装前请自行检查仓库内容、依赖和所需权限。

05

同步与移除

公开数据按计划定时刷新。新仓库不会立即出现，元数据也可能在下一轮同步前保持旧值。

不再满足条件、已归档或被隔离的插件会从公开列表移除。为避免异常同步覆盖健康数据，数量大幅下降或发现不完整时会停止发布新快照。
